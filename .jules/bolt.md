## 2025-10-24 - [Avoid linear array search in component-level $derived runes]
**Learning:** Performing a linear array lookup (`array.find()`) inside component-level `$derived` runes results in an $O(N)$ computational cost per active component instance. When many instances exist (such as active `MessageBubble` instances in a chat window), any store state mutation causes every single component instance to trigger its derived computation, leading to $O(N^2)$ overall complexity on updates. Defining a reactive, O(1) getter map/record on the `$state` store itself reduces lookup complexity to $O(1)$ and overall update complexity back down to $O(N)$.
**Action:** Always map store array states to an O(1) record lookup on the store itself using reactive getters, and reference that map in component $derived runes instead of executing direct array searches.
